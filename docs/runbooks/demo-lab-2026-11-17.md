# Demo runbook: AI for Good Lab walk-through, 17 November 2026

Two scenarios live on `dev`, for the AI for Good Lab group meeting on Tuesday 17 November 2026 at 15:00 CET (#639):

- **Scenario A, publish and evaluate:** a host publishes a public dataset through the wizard, the manifest appears in the Croissant index, and a predictions file is scored on the IDRiD grading task.
- **Scenario B, controlled access:** a researcher requests a restricted dataset, the holder approves, the researcher signs the data use agreement, receives GA4GH Passport visas, and downloads the files.

Scenario E (sealed container run next to the data) is shown from the diagram only. The runner isn't deployed (#634).

Demo data is created by [`apps/api/scripts/lab-demo.ts`](../../apps/api/scripts/lab-demo.ts), through the API with real accounts. Commands below run from the repository root with `API_BASE=https://dev.oci.ai4h.net`.

## Prerequisites

The dev deploy must include #660 (Passport signing key) and #661 (requester e-mail for the identity score). Without #660 no visa is issued; without #661 every request shows the host a tier conflict.

Two accounts on dev, each with its own mailbox that you can read during the demo:

| Account        | Role                                    | Needs                                                                                                                          |
| -------------- | --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| **Holder**     | Data holder; publishes and approves     | Member of the `host` group (an admin adds it in `/admin/users`).                                                               |
| **Researcher** | Requests access, submits, signs the DUA | A verified address on an **institutional** domain, so the identity score reaches the dataset's REGISTERED tier. Not in `host`. |

Sign up at `https://dev.oci.ai4h.net/signin`. Each account's access token is on `/dashboard` (copy button); tokens last one hour.

## If something goes wrong

| Symptom                        | Likely cause and fallback                                                                                                                        |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| `check`: JWKS lists 0 keys     | #660 isn't deployed, or the API couldn't reach KMS at boot (see the API log for "Passport signing key not ready"). Show B5 from the diagram.     |
| B3 shows a tier conflict       | The researcher's address isn't verified or isn't institutional, or #661 isn't deployed. The holder can still approve; say the verdict is a hint. |
| `seed`: 403 on create          | The holder isn't in the `host` group yet; sign out and in again after adding it, so the token carries the group.                                 |
| B4: no mail after 2 minutes    | Use the signer link printed by `sign`.                                                                                                           |
| `submit --scored`: quota error | Three scored submissions this week already. Show the earlier result on the leaderboard.                                                          |
| Any token error                | Tokens expire after an hour. Copy a fresh one from `/dashboard`.                                                                                 |
